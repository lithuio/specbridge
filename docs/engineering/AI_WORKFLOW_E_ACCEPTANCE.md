## 贯穿示例：客户门户登录与报表

准备合成需求：“客户希望在门户登录后查看自己公司的报表；登录方式、报表保留时长和导出格式尚待确认。”准备两个TXT文件：对客背景写“只允许查看本公司报表，导出能力尚未批准”；内部背景写“内部预算讨论，不能对客公开”。不要使用真实客户文件或真实个人信息。

| 人工场景 | 操作与应见结果 |
|---|---|
| 项目背景 | 创建项目后可选上传；内部文件默认Client不可见。Owner明确共享对客文件版本后Client可见；替换文件不会自动共享新版本。查看来源能定位版本/页段。失败不撤销已创建项目。[B详细范例](AI_WORKFLOW_B_MANUAL.md) |
| 只问问题 | Requirement中选择“帮我问清楚”，编辑、选择一个问题，例如“采用密码、验证码还是企业SSO？”；保存个人稿后刷新仍在，其他作者不可见。明确发布后只出现所选问题，无Revision、Ready或审批。[A详细范例](AI_WORKFLOW_A_MANUAL.md) |
| 只整理规格 | 选择“帮我整理规格”，编辑内容和验收标准，未确认SSO不能变成事实。先保存个人稿，预览后明确创建Revision。原始输入和旧Revision保持；Ready仍须单独点击。另一窗口改变业务版本后确认应409且保留编辑。 |
| Copilot问答 | 请求“本项目现在缺少哪些确认？下一步由谁处理？请附真实版本来源”。答案应区分状态事实与建议，来源属于当前项目。Client不能见内部背景或供应方商业草稿；聊天关闭/切换项目不能带入其他项目敏感内容。 |
| Copilot准备并确认 | 从真实需求来源准备问题、规格或商业草稿；在独立提案区编辑、保存、预览再明确执行。准备不改变业务，确认只执行当前白名单动作；商业估算与金额需人工填写，不能自动Submit/审批/验收。[C详细范例](AI_WORKFLOW_C_MANUAL.md) |
| 连接本地Codex | Owner复制无秘密命令，在目标代码目录连接，核对项目、指纹、期限后网页确认。通过Codex自身项目信任提示，重新打开项目核对MCP与Skill自动加载；此实际用户信任步骤仍待H-20人工验收。[D安装与恢复](AI_WORKFLOW_D_MANUAL.md) |
| 外部批准规格 | 先用原人工流程形成Ready规格、商业草稿、Submit、Owner批准、Client批准。给Codex：`使用 $requirement-analyst 读取门户登录的明确批准版本，区分批准事实、引用背景和推测；给出范围内实施建议与验收清单，判断导出是否已批准。不要修改文件。` 应实际调用两个只读工具，附批准版本和Revision来源；没有批准规格时说明为空，不能读取内部背景和草稿。 |
| 凭据撤销 | Owner网页撤销连接Token，再调用工具应拒绝。重复安装/检查不能产生第二Token；卸载保留其他配置，远端撤销与本地卸载是两个动作。明文不能出现在命令、URL、日志、项目配置或浏览器持久存储。 |
| 异常和手动业务 | 使用Mock测试分别复现超时/限流/空响应/503；观察输入保留与明确重试。关闭AI后仍能手动问答、写Revision、商业审批和交付验收；未知写入结果先查回执，不重复创建。不要为模拟异常撤销真实Provider Key或耗尽真实付费账户。 |
