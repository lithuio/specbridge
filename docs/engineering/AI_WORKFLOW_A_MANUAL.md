# AI工作流 A — 人工测试范例

适用本分支的新需求工作台。前提：目标库已经明确获批并应用0005。本轮只应用5434/specbridge_test；开发5433/生产没有由本轮迁移。不要在未审核0006的情况下复制候选SQL到生效journal。

沿用现有启动命令 `DEEPSEEK_ENABLED=true pnpm dev:api`、`pnpm dev:web`，密钥仍只由API从本地.env加载，不复制到浏览器或配置说明。无需为保存个人工作稿启用AI；API/数据库可用即可手动操作。

## 1. 只澄清，不创建Revision

Owner新建合成项目“青禾需求导出”，初始范围“项目需求协作与人工范围确认”。创建需求“按月导出需求”，原文：

> 客户希望按月份导出项目需求，用来每周核对范围。暂未确定导出字段、文件格式和谁可以导出。不要自行假定权限或数据范围。

进入需求工作台，选“帮我问清楚”，指令填写：

> 先提最多三个会影响实现范围的问题，解释为什么要问。不要写规格，也不要假定客户已经确认。

点击生成，核对建议预览。此时问答数、Revision、业务版本应完全不变。选择采用到工作稿后，可改写、移除问题和假设/风险；勾选待发布问题。“保存个人工作稿”只保存本人私有内容，刷新可恢复，其他用户看不到。先发布一个问题：预览→确认发布问题。只有所选问题进入正式问答，未选条目仍留在个人稿；不会产生Revision。

使用原“回答问题”表单记录真实确认，例如“导出标题、状态、负责人；仅项目成员导出本项目可见内容；格式待确认”。再次生成澄清建议时会包含已有问答；必须核对AI是否仍重复已回答的问题，不把建议当作客户事实。

## 2. 只整理和保存规格工作稿

选“帮我整理规格”，指令：

> 根据原文和已记录回答整理规格。保留未确认的导出格式，不补成CSV。验收标准必须能观察验证。把未定事项单独列出。

生成→核对来源版本/预览→采用到工作稿。编辑正文和验收标准，删除不合适条目。保存个人工作稿后刷新，内容应恢复，但“最新Revision”仍保持原值；可隔天继续编辑，无需立即发布。

完成核对后，预览创建Revision→确认创建Revision。只发布正文与验收标准，私有假设/风险/未决问题不会自动发布。发布前删去正文中“未保存草案”等可能过时的状态自述，实际保存/批准状态以页面对象和版本为准。正式Revision不可修改，原文保持，需求为CLARIFYING。AI不会Mark Ready、Submit、批准或验收；这些仍使用原人工流程，待回答正式问题会阻止Ready。

## 3. 冲突、未知结果与失败恢复

- 两个标签打开同一需求。在第二页新增正式问题，第一页发布旧稿应409，输入保留。核对最新业务后点击“已核对最新需求，继续编辑”，保存新版工作稿，再明确预览发布。
- 两个标签编辑本人同类型工作稿，后保存的旧版本应409。点击“核对已保存工作稿，保留当前输入”，比较远端内容，再决定是否保留当前输入继续；不会静默覆盖。
- 保存/发布时网络断开：不要另建发布操作。查询发布结果，未查到时才人工重试同一发布；回执防重复。刷新后也应先检查工作稿的已发布标记和正式记录。
- AI超时/不可用/限流时仍可手写并保存工作稿、使用原业务表单。不要为了演示故障大量调用付费API；Mock浏览器套件已覆盖429、503、格式无效和超时。
- “删除个人工作稿”需要再次确认，删除后正式问题/Revision及回执仍保留。

## 4. 角色和其他功能

绑定Client后，其账号只出现澄清任务，且不能读Owner/Developer个人稿；供应方能用两种任务，Owner也不能代读他人的私有稿。退出/换号/撤权后旧私有内容不可恢复；同账号会话复核应保留输入并恢复按钮。
