# ADR-001：采用模块化单体，而非微服务

- **状态**：Accepted（MVP 架构方向，技术实施仍需评审）
- **日期**：2026-11-01

## 背景

SpecBridge 在两周内交付多租户身份、需求版本、审批、交付、AI 集成的 MVP。核心操作需要单数据库事务确保审批一致性，团队主要由开发者和 Coding Agents 协作。

## 决策

采用 pnpm Monorepo；Next.js 负责 Web，NestJS 单一模块化 API 负责领域服务，PostgreSQL 作为单一事务数据库。通过模块边界和契约维持可维护性，而不是分成独立微服务。

## 备选方案

1. Next.js 全栈 Server Actions：部署最少，但独立 API/Agent 集成及授权边界更难清晰展示。
2. 多微服务 + 消息总线：可独立扩展，却增加部署、网络、事务与测试复杂性。

## 代价

当前 API 必须整体部署；局部模块不能单独扩容。初期可接受，未来有确定负载再拆分。

## 验证

一个 NestJS 服务完成主流程；API 模块各自可单测/集成测；部署组件不超过 Web、API、Postgres、反向代理及可选 MCP。
