# 使用指南

[项目首页](../../README.md) · [文档中心](../README.md) · [安装与启动](GETTING_STARTED.md)

本指南以“客户门户增加报表导出”为例，说明怎样从需求走到验收。操作前先启动服务并完成注册；没有预置演示账号。完整人工验收场景见 [AI 工作流综合验收](../engineering/AI_WORKFLOW_E_ACCEPTANCE.md)。

## 角色与准备

| 角色                  | 主要操作                                                                       |
| --------------------- | ------------------------------------------------------------------------------ |
| Owner（供应方负责人） | 创建工作空间 / 项目、管理成员与客户、共享背景资料、供应方审批、管理 Agent 凭据 |
| Developer（开发者）   | 在分配项目内澄清需求、整理规格、评估变更、提交交付；不能代替双方审批           |
| Client（客户审批人）  | 在绑定项目内提出需求、参与问答、批准冻结版本、验收交付                         |

角色来自工作空间和项目关系，同一账号在不同项目可以有不同身份。演示时建议使用三个独立浏览器配置，避免同一浏览器共享登录会话。Developer 和 Client 都需先注册，再由 Owner 通过已有账号邮箱分配。

## 1. 建立项目

1. Owner 登录，在「工作概览」创建工作空间。
2. 创建项目，例如“青禾客户门户”，填写初始范围：“客户登录后查看本公司报表，导出能力另行确认。”
3. 在工作空间成员页加入 Developer，再到项目成员页分配该开发者。
4. 在项目成员页绑定唯一 Client。Client 从「我的项目」进入，无需加入供应方工作空间。

初始范围创建后不可修改，它是参考快照，不代表双方已在平台签署初始合同。项目可以暂时没有 Client，但正式提交变更前必须绑定；首次正式提交后不能通过当前公开 API 更换客户。

## 2. 提出需求并完成澄清

Client 在项目「项目需求」中新建需求，例如：

> 希望每月导出本公司的报表，用于财务核对。导出字段、格式和可用人员尚未确认。

保存后，Owner / Developer 提问，Client 回答。建议先确认影响范围的事项：

| 问题                 | 示例答复                     |
| -------------------- | ---------------------------- |
| 需要哪些字段？       | 日期、订单编号、金额         |
| 导出格式是什么？     | CSV                          |
| 谁可以导出哪些数据？ | 客户账号仅导出本公司可见报表 |

三角色可按权限参与问答。需求原文只在草稿状态由作者或 Owner 编辑；正式问题和回答通过追加记录保留，不能直接修改已有问答。当前所有问题均需有答复，才可继续标记就绪。

## 3. 整理规格并标记就绪

Owner / Developer 将已确认结论整理为新规格版本，写明正文和可验证的验收标准，例如：

- 选择月份后可导出该月 CSV，包含日期、订单编号和金额。
- 导出结果仅包含当前客户可访问的本公司报表。
- 选择没有记录的月份时，界面给出明确反馈。

创建 Revision 后，再人工执行「标记就绪」。需要存在有效的最新规格、非空验收标准，且没有未答问题；保存个人稿或创建 Revision 都不会自动完成就绪确认。

**Revision 是不可变历史。** 后续变动应创建新版本；新版本创建后回到澄清中，需再次标记就绪。就绪状态下不能直接追加问答；若相关变更正在审批，必须等待批准或拒绝后才能新建 Revision。

## 4. 评估范围与商业影响

从就绪需求详情创建商业评估，Owner / Developer 填写范围说明、预计工时、费用增量、币种、工期变化和验收标准。

| 字段     | 示例与含义                                                          |
| -------- | ------------------------------------------------------------------- |
| 范围     | 增加指定月份报表的 CSV 导出                                         |
| 预计工时 | `8` 小时，须非负                                                    |
| 费用增量 | CNY `50000` 表示增加 **500 元**；输入整数最小货币单位，支持零和负值 |
| 币种     | `CNY`，需人工选择                                                   |
| 工期变化 | `1` 天；按实际影响填写，可为零                                      |
| 验收标准 | 本次双方应核对的明确标准                                            |

先保存草稿，再正式提交。只有提交才生成不可变的变更版本，冻结所引用的最新就绪规格与商业字段。Client 看不到供应方商业草稿；正式提交后可以查看冻结内容。

原范围内的澄清若需在平台完成正式交付，也使用变更单，可填写零费用、零工期增量。

## 5. 双方依次审批

1. Owner 在「变更与审批」中核对冻结版本、金额、工期与验收标准，批准或拒绝。
2. Owner 批准后，Client 对**同一个版本**核对并批准或拒绝。
3. 双方都批准后，才能为该版本提交交付。

任一方拒绝后，供应方可重开草稿、修改并再次正式提交。新提交产生新版本，双方重新审批，旧决定保留。已经批准的变更不能重开覆盖；新增范围使用新的需求修订和新变更单。

## 6. 提交交付并验收

Owner / Developer 从已批准变更详情提交 HTTPS 成果链接、交付说明和可选 HTTPS 证据链接。交付不接收附件上传，也不自动抓取链接；背景资料上传是独立功能。

Client 打开交付详情，对照批准规格和验收标准：

- **验收通过**：记录接受结果，该批准版本的交付闭环结束。
- **退回修改**：填写具体意见；供应方改进后新建一条交付，再由 Client 验收。

旧交付与意见始终保留。同一批准版本同时只能有一条待验收交付，已验收后不能继续提交新交付。可在版本历史、交付历史和「活动记录」核对相关记录；各角色只看到其有权访问的内容。

## 7. 使用项目背景资料

Owner / 被分配的 Developer 可在「背景资料」上传文本 PDF、DOCX、Markdown 或 TXT，单文件最多 10 MiB；扫描件不提供 OCR。项目创建后也可补充，解析失败不阻断手动协作。

- 默认内部可见；**只有 Owner 明确共享的具体版本**对 Client 可见。
- 替换上传生成新版本，不会自动将新内容共享给客户。
- Owner 可撤回共享或停用资料；重新启用不会自动恢复共享。
- 页面展示授权解析文字和版本来源，不提供原件下载。

对客澄清 / 规格建议只使用已共享背景。Copilot 按当前角色读取资料，供应方可能看到内部资料；内部参考不能被视作客户已确认的事实。详细限制与错误处理见 [背景资料手册](../engineering/AI_WORKFLOW_B_MANUAL.md)。

## 8. 使用 AI 与 Copilot

AI 是可选辅助；先按 [运行指南](GETTING_STARTED.md#可选启用-ai) 配置。未配置时可以手写工作稿、使用原业务表单完成主流程。

### 需求工作台

| 操作                     | 实际结果                                              |
| ------------------------ | ----------------------------------------------------- |
| 「帮我问清楚」生成建议   | 得到待核对的问题，不自动写入正式问答                  |
| 「帮我整理规格」生成建议 | 得到待编辑的正文与标准，不自动创建 Revision           |
| 保存个人工作稿           | 保存本人内容，刷新可恢复；其他账号包括 Owner 不能代读 |
| 预览并确认发布问题       | 只发布所选问题                                        |
| 预览并确认创建 Revision  | 供应方创建正式规格；不会自动标记就绪                  |

Client 仅有澄清任务；创建规格仍由 Owner / Developer 完成。发布前核对 AI 的假设、来源和未确认事项，避免把建议变成未经客户确认的承诺。

### 项目 Copilot

顶部「Copilot」可询问项目状态、阻塞点和下一步，答案附业务来源；进入项目页面时关联当前项目，其他页面需先选择有权访问的项目。

从需求来源或个人提案区准备操作后，依次编辑、保存预览、核对并明确确认执行。支持的有限操作包括发布问题、创建规格及创建 / 更新商业草稿，仍受原权限和版本规则约束。Copilot 不会自动标记就绪、正式提交、审批或验收；商业金额和估算由人填写。

聊天仅保存在当前浏览器内存。已保存工作稿和提案可以恢复，提案 24 小时后不能执行；刷新前先保存需要保留的编辑。更多例子见 [提案手册](../engineering/AI_WORKFLOW_C_MANUAL.md)。

## 9. 连接外部 Agent

先通过人工流程产生双方批准的规格。Owner 在项目「访问凭据 → 连接本地 Codex」填写 SpecBridge 仓库和目标代码目录，生成命令并在本地执行，随后在网页核对项目、连接指纹和权限后授权。

本地 MCP 仅暴露 `list_project_requirements` 与 `get_approved_spec` 两个只读工具，外部 Agent 只能读取该项目的批准规格，不能读取内部背景、草稿或执行审批。连接授权独立于 DeepSeek；安装器支持 Linux / WSL，不自动改变用户的项目信任设置。

可在网页撤销凭据以阻止后续读取。安装、恢复、撤销与卸载步骤见 [MCP README](../../apps/mcp/README.md)；已经发送到宿主的内容不会因撤销而被收回。

## 操作受阻时

| 提示 / 现象               | 应怎样继续                                   |
| ------------------------- | -------------------------------------------- |
| 缺少 Client，无法正式提交 | Owner 在项目成员页绑定唯一已注册客户         |
| 仍有未答问题，无法就绪    | 完成正式问答，再核对最新规格与标准           |
| 审批中，无法创建 Revision | 等待当前批准 / 拒绝决定，不覆盖冻结内容      |
| 版本冲突 / 409            | 保留输入，刷新并核对最新记录，再明确重新操作 |
| 保存 / 提交结果未知       | 先查列表、历史或回执，不连续点击创建或审批   |
| 无权限 / 403 / 404        | 核对当前账号、项目分配与来源归属             |
| AI 失败或限流             | 保留编辑，使用手动表单；按提示等待后重试     |

业务规则的正式定义见 [状态机](../architecture/STATE_MACHINES.md) 和 [验收标准](../product/ACCEPTANCE.md)；本页帮助操作，不替代产品基线。
